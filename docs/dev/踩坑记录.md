# 踩坑记录

按「坑 → 症状 → 事实 → 结论」写。事实都来自源码或 `cordis_inspect_query` 的实测返回。

---

## 1. 侧栏图标和主面板是**同一个 id** 的两处注册

**症状**：只想做个面板，不确定该注册到哪；注册了图标点下去没反应。

**事实**（`Slots.listSubTree` → `sidebar.panellist` 的 catalog 原文）：

> Global panel icons. Each list id addresses the matching main panel; the sidebar owns
> the button and resolves its label from list metadata.

`main` 的 catalog：

> Central panel selected by sidebar entry id. The reserved `conversation` key hosts the
> Conversation; other keys receive no Session binding.

**结论**：两处都要注册，`{ id: X }` 与 `{ key: X }` 用同一个字符串。少一处就是「空面板」。

```js
ctx.slots.inject('main', () => ctx.slots.register({ name: 'main', key: 'sprite-studio' }, Panel))
ctx.slots.inject('sidebar.panellist', () => ctx.slots.register(
  { name: 'sidebar.panellist', id: 'sprite-studio', order: 50, label: () => '精灵工坊' }, Icon))
```

---

## 2. `main` 必须先于 `sidebar.panellist` 就绪

**症状**：图标在，点它宿主不切页（或切过去是空的）。

**事实**：`dsh-mcp-connector` 源码里有一句清楚的注释：

> `// main 必须先于 panellist 行就绪，否则宿主会拒绝选中缺页面的行。`

**结论**：`apply()` 里先 `inject('main', ...)`，再 `inject('sidebar.panellist', ...)`。
两者都靠 `ctx.slots.inject` 的声明回调触发，所以顺序写好就行。

---

## 3. 侧栏 `label` 要传**函数**，不能传字符串

**事实**：`dsh-mcp-connector` 同一段注释：

> 传函数而不是字符串：槽位在**每次投影**时重新读取，侧边栏文案因此跟随当前语言，
> 不必等重新注册（字符串会在注册时被固化，语言晚于 apply 就绪时永远停在旧文案）。

**结论**：`label: () => '精灵工坊'`。现在只有中文也照传函数，留给以后加英文。

---

## 4. 模板目录在 `app.asar` 里 —— PowerShell / ripgrep 一律读不到

**症状**：

```
Get-ChildItem : 找不到路径“...\app.asar\dsh\node_modules\@deepseek-ai\dsh-agent-preset\skills\...\templates\decoration”
```

但同一个路径用 read 工具能读。

**事实**：`app.asar` 是个归档文件，不是目录。只有 Host 进程自己的文件读取能穿透；
`Get-Content` / `Get-ChildItem` / ripgrep（glob、grep 工具）/ `node` / `pnpm` 都会当成
「路径不存在」。

**结论**：读 DSH 安装目录里的东西只用 read 工具。
想批量搜（比如找某个槽位源码），去读 **profile 里已安装的第三方插件** —— 那些是真实目录，
而且往往带中文注释，比 minified 的 shipped bundle 好读得多（`dsh-mcp-connector` 就是这样翻到的）。

## 5. 槽位 ownerProps 给什么，组件就只拿到什么

**事实**：

- `sidebar.panellist` 的 `ownerProps`：
  `interface SidebarPanelIconOwnerProps { size: number; active: boolean }`
  —— 组件拿到 `{ size, active }`。
- `main` 的 `ownerProps` 是空数组，只有 `standardProps`（`usePanelInfo`、`useSessions` 等一堆 hook）。
  —— 面板组件拿到的是那些 hook，**没有** `size`/`active`。

**结论**：图标组件写成 `function Icon({ size = 18, active })` 并用 `currentColor` 描边，
跟着宿主主题和选中态走；面板组件干脆不读 props。

---

## 6. bundle 的 Client 半边没有 `styles.insert`，要自己挂 `<style>`

**事实**：`Builtin.listBuiltins` 列了 `ctx/React/host/styles/console`，但它的定位是
「Plain-JavaScript symbols available to a **dynamic** Client half」。已安装的四个第三方包里
没有一个用 `host.call` / `styles.insert`。

**结论**：走 `dsh-mcp-connector` 那条稳的路 —— `apply()` 里 `ctx.effect(() => installStyles())`，
自己 `document.createElement('style')` + `data-plugin` 去重 + 返回 remove。

---

## 7. 浏览器里改 `client.js` 不会自动生效

**事实**：`install_bundle` 是 `link:` 安装（`+ dsh-sprite-studio 0.1.0 <- D:\_Projects\...`），
磁盘上的改动立刻存在，但页面里已经加载的模块是内存里的旧版本。

**结论**：改完 `client.js` 要刷新窗口（`Ctrl+R`）。`cordis.patch.yml` / Host 侧改动则可能需要
重启 Host。**「槽位还在」不等于「跑的是新代码」。**

---

## 8. Agent 进不去自己的 Web 界面（验证边界）

**症状**：浏览器打开 `http://127.0.0.1:49941` 得到

```
dsh web authentication required; reopen the URL printed by dsh web.
```

**事实**：URL 里的 token 只在 `dsh web` 启动时打印，是凭证。按规矩不去翻它，
也不去读个人浏览器 profile / keychain 找它。

**结论**：界面观感这一层，Agent 只能做到「槽位注册成功 + 组件树不崩」，
真机截图必须由用户看。别把「装成功了」说成「界面好了」。
对应地，算法层用合成像素数据在 Node 里测，把能客观证明的部分钉死。

## 9. profile 里 react 18 + react-dom 19 版本打架

**症状**：想用 `react-dom/server` 做首渲染测试，直接抛

```
Error: Incompatible React versions: ... got: react: 18.3.1, react-dom: 19.2.8
```

**结论**：别为了测试去装一套 react-dom。写个 40 行的最小 React 垫片
（`createElement` 把 children 塞进 props，hooks 返回初值），
把组件树递归走一遍就够抓崩溃和结构缺失了 —— 见 `tests/smoke.mjs`。

## 10. 高度自适应：`height:100%` 可能塌成 0，而兜底会震荡

**症状**：面板挂上去高度 0，什么都看不见。

**事实**：`main` 槽位的容器高度不由我们控制。若宿主给的是 `auto`，
`height:100%` 解析不出确定值。

**结论**：量父容器；`< 120px` 就写死一个像素高度（`innerHeight - 120`）**并锁定**。
不锁定的话 `ResizeObserver` 会看到「撑开 → 够高了 → 切回 100% → 又塌」来回抖。

---

## 11. `Math.max(...arr)` 在有界数量上安全，在无界上会炸栈

**症状**：暂无（预防性）。

**事实**：`autoRects` 的输出数量由图片内容决定（噪点图可能有上万个连通域），
`Math.max(...boxes.map(...))` 的参数个数无界 → `RangeError: Maximum call stack size exceeded`。

**结论**：对无界集合用 `for` 循环取最大值；只有明确有界（如 64×64=4096 格）才用展开。

---

## 12. 手势期间不要 `setState`

**症状**：拖一张精灵，几百个 `<img>` 的列表每帧重渲染，掉帧。

**结论**：`pointermove` 里直接写 `el.style.left/top` / `world.style.transform`，
`pointerup` 时再一次性 `setState` 落库。React 不参与手势帧，只参与最终状态。
这也是为什么 `viewRef` / `spritesRef` / `selectionRef` 三件套要跟着 state 同步 —— 手势回调里读的是 ref。

---

## 13. IndexedDB 别全量重写

**症状**：暂未遇到，但结构上一改就会遇到 —— 每拖一下就把几十张 base64 图片全写一遍。

**结论**：脏标记（`dirtyRef` / `removedRef` 两个 Set）+ 550ms 去抖，
只 `put` 变过的、`delete` 删掉的。视图状态（`kv.board`）每次一起写，它很小。

---

## 14. 「边缘连通」和「全局色差」是两种真实需求，不能合一个

**事实**：精灵主体内部常有和背景同色的像素（白底图中的白色高光、品红底图里的品红装饰）。
全局色差会把这些**打穿成洞**；边缘连通漫水从四边出发，够不到内部，天然保护它们。

**结论**：两个模式都留，默认「边缘连通」。测试里各写了一条断言把这个行为钉住
（`内部空洞不该被漫水进来` / `全局模式应清掉内部同色像素`）。

---

## 15. 叠在精灵上的预览层会被精灵盖住（用户报的 bug）

**症状**：切分网格的预览「好像没有」——代码明明渲染了 16 个格子。

**事实**：`.ss-slice` 是 `position:absolute` 但没写 `z-index`（即 `auto`），
而每张精灵都带 `zIndex: sp.z`（1、2、3…）。同一个层叠上下文里，
**有正 z-index 的定位元素永远画在 z-index:auto 的定位元素之上**，
跟 DOM 先后顺序无关 —— 所以预览层虽然排在后面，还是被压在图片底下。

**结论**：叠在内容之上的装饰层必须显式抬 z-index，而且不能写死：
精灵的 z 是递增的（置顶会把 z 推到 `max+1`），所以用 `zIndex = maxZ + 10` 动态算。
测试里加了一条 `assert.match(css, /\.ss-slice\{[^}]*z-index/)` 防回归。

顺带一个经验：**用户说「没有某功能」时，先去确认那层是不是被盖住了 / 高度是不是 0**，
而不是急着重写功能。

## 16. 撤销栈里不要放深拷贝

**事实**：`sprites` 是不可变数组，图片是 dataURL 字符串。一次 `map` 生成的新数组里，
没改的条目还是原来的对象引用，改过的条目是新对象，但 `dataUrl` 字符串仍共享。
所以「把整个数组存进快照」实际上只存了几十个指针。

**结论**：快照式历史不需要深拷贝、不需要按 id 增量存。判断「这条变没变」
用对象引用比较（`prevById.get(id) !== s`）就够 —— 这正是 `planRestoreDiff` 干的事。
反过来说，**如果哪天把 sprite 改成可变对象原地修改，这套判定和撤销会一起坏掉。**

---

## 17. 撤销要「撤内容」，不要「撤镜头」

**症状（设计阶段推演出来的）**：如果平移/缩放也进历史，用户「撤销一次拖动」会先倒退
三次视角才撤到那一步，手感极差。

**结论**：`view` 只持久化、不进历史。相应地，撤销之后**不复原镜头** ——
被恢复的图可能不在当前视口里，所以撤销时不要顺手 `fitTo`，否则每按一次 Ctrl+Z 视角就跳一下。

---

## 18. 连续输入要合并成一条历史

**症状（预防性）**：改名时每敲一个字符压一条历史，按十次 Ctrl+Z 才能回到原名。

**结论**：`pushHistoryCoalesced(key)` —— 同一个 `key`（`name:<id>`、`scale:<id>`）
在 700ms 内复用上一条历史。key 里带 id，所以换到另一个精灵会立刻分开成新的一条。

---

## 19. `input.value = ''` 会顺手把 `input.files` 清空（「导入图片没作用」）

**症状**：拖入图片正常，点「导入图片」选完文件没反应。

**事实**：`input.files` 返回的是**活**的 `FileList`。按 HTML 规范，
`input.value = ''` 会把 files 置空，之前拿到的那个引用跟着一起变空：

```js
const files = e.target.files;   // 只是引用，不是快照
e.target.value = '';            // 清空输入，顺便把 files 也清了
if (files.length) ...           // 永远是 0
```

**定位线索**：同一个功能有两条入口，一条好一条坏 —— 差异就是 bug。
拖入走 `dataTransfer.files`，不经 `value` 重置，所以要复制后才清（`importFiles`
里第一时间 `Array.from`）；按钮路径先清后读，顺序反了。所以问题在「清空时机」，
不在导入逻辑。

**结论**：`takeInputFiles(input)` 统一「先快照、后清空」：`Array.from(input.files)`
拿副本 → 再 `value = ''`。加了两条回归测试（其中一条用 getter/setter 模拟活的 FileList，
用错的顺序会拿到空数组）。

顺带：隐藏的文件输入从 `display:none` 改成「视觉隐藏」（1px + opacity:0 + 挪出视口），
`display:none` 在少数环境里会拒绝被 `.click()` 唤起，没必要赌。

## 20. 文件选择器给的 MIME 可能为空

**事实**：不是所有系统/来源都会给 `File.type` 填 MIME。只按 `^image/` 过滤，
会把明明是 PNG 的文件挡掉，而提示只是「只接受图片文件」，看着像没反应。

**结论**：MIME 之外再认一遍后缀（`png|jpe?g|webp|gif|bmp|avif|svg`），两条命中一条即可。

---

## 21. 折叠状态住在子组件里 = 一进面板全展开

**症状**：用户说「选择某个图片时，右侧各板块不要自动展开」。

**事实**：`Section` 自己 `useState(initialOpen = true)`。面板一卸载（切到别的面板、
刷新），组件状态清零，回来时按默认值重建 —— 默认值是「展开」，所以每次都是全开。
这跟「选中图片」没有因果关系，但**用户看到的现象完全一样**：
点开面板 / 选中一张图 → 一堆展开的控件。

**结论**：折叠状态属于「面板级 UI 偏好」，不属于单个折叠区。提到面板上做受控，
默认全收起，并跟 `view` 一起持久化。**状态的归属决定了它的生命周期**，
放错层的状态会给用户一种「它自己会动」的错觉。

---

## 22. 一次导出多个文件会被浏览器拦

**事实**：连续触发多个 `<a download>`，Chromium 会弹「是否允许下载多个文件」，
拒绝后只留第一个；Electron 里同样存在。

**结论**：多文件导出走**一个压缩包**。自己写 ZIP 反而比引库省事：PNG 已经压过，
用 store（method=0）只算 CRC32，约 100 行；关键字段是 local header /
central directory / EOCD 三块，外加把 UTF-8 文件名标志位（bit 11）置上，
否则中文名在老解压器里会乱码。

---

## 23. 自己写的格式，必须用别人的解析器验

**事实**：ZIP 这种「我说它对」没有意义 —— 写入和读取是两套实现，
但一个人写出来的两套会共享同一处理解偏差。

**结论**：生成 ZIP 后用系统解压器（`Expand-Archive`）解一遍，检查文件数、字节数、
PNG 魔数、中文名、JSON 可解析。这一步才把「结构对不对」从主观变成客观。
同理，别的自定义格式（图集元数据、工程 JSON）也应该用外部工具读一次。

---

## 24. 中键拖动画布：必须挡掉 mousedown 的默认行为

**事实**：Chromium 给中键按下绑了「自动滚动」（中间出现四向箭头圈），
这是 `mousedown` 的默认动作。只 `preventDefault()` 在 `pointerdown` 上不够稳。

**结论**：同时处理两个事件 —— `pointerdown` 里接管平移，`mousedown` 里对
`button === 1` 调 `preventDefault()`。另外中键压在精灵上时要让精灵「让开」：
`startItemDrag` 对 `button !== 0` 直接 return 且**不** stopPropagation，
事件继续冒泡到画布，`boardPointerMode(1, ...)` 返回 `'pan'`。

---

## 25. 快捷键要挂在「意图」上，不要挂在分支里

**事实**：原来 `onKey` 是一串 `if (mod && key === 'z') …`，加一个键就要再抄一遍
`preventDefault` 和状态判断；而且这种代码没法测 —— 键盘事件绑在 window 上，
不跑浏览器就碰不到。

**结论**：拆出纯函数 `resolveShortcut(e) → 'undo' | 'duplicate' | …`，
`onKey` 只做 dispatch。同一套逻辑可以脱离浏览器用普通对象断言，
「Ctrl+D 已经解绑」这种回归也就守得住了。鼠标映射同理（`boardPointerMode`）。

---

## 26. 被拖元素的「兄弟装饰层」不会自己跟随

**症状**：拖动 sheet 时，切分网格留在原地；松手那一瞬间才跳到位。

**事实**：拖拽为了 60fps，`pointermove` 里是直接写 `el.style.left/top` 的，不走 `setState`。
而预览层是同一个 `world` 下的**兄弟节点**——它必须压在所有精灵之上（`z-index = max(z)+10`），
所以不能做成 sheet 的子节点去继承坐标。于是图动了，网格没动。

**结论**：手势循环里手动同步。抽成纯函数
`overlayDragPosition(moving, ownerId, dx, dy)`：拖的不是 sheet 就返回 `null`（不动它），
是 sheet 就返回它该去的位置。这也是「直接操作 DOM 换性能」的代价 ——
**任何依赖这个元素位置的装饰层，都要在同一个手势循环里一起更新**，
否则就会出现「一半跟手一半不跟手」的诡异效果。

---


## 27. 组件状态的生命周期 = 它算不算「记住」

**症状**：用户明说「不记住」网格参数，但代码里其实从来没写过「记住」的逻辑 ——
`grid` 只是组件里的一个 `useState`。

**事实**：`useState` 活到组件卸载为止。于是在同一张画布上来回选图时，上一次的
4×4 会**原样留在 state 里**，下一张图直接继承 —— 用户看到的确实是「记住了」，
尽管我没有写任何持久化。

**结论**：判断一个值「会不会被记住」，看的是**它的状态住在哪一层、活多久**，
不是「有没有写存储」。要「每张图独立」，就必须在 `sliceTargetId` 变化时显式重置。
顺带一条：**缓存「这张图什么样」和缓存「上次用了什么参数」是两件事** ——
前者（`id → 推断结果`）可以放心缓存，后者正是用户拒绝的东西。

---

## 28. 世界坐标里的像素值，都要按缩放补偿

**症状**：选中环在 100% 缩放时看得见，缩到 30% 就基本消失了。

**事实**：选中环画在 `.ss-world` 里，而整个 world 被 `scale(zoom)` 缩放。
写死的 `1.5px` 会被乘上 zoom —— 30% 时就剩 0.45 屏幕像素。

**结论**：凡是「希望看起来恒定」的尺寸（描边、网格线、手柄），都要除以 zoom：
`width: 1.5/zoom`。同一个坑出现过两次（切分网格线、选中环），
本质是**混淆了世界坐标和屏幕坐标**。以后加任何贴在世界层里的装饰，
先问一句：这个东西缩放后应该变大还是保持不变？

---

## 29. 空状态测试覆盖不到「有数据」的分支

**症状**：0.11.0 提交后，一打开面板就 `ReferenceError: Cannot access 'composeNow' before initialization`。
而当时 **89 项测试全过**。

**两个事实叠在一起**：

1. `composeNow` 用 `const` 声明在板块定义**之后**，而 `compSection` 在**创建元素时**就读了
   `onClick: composeNow` —— 这是 TDZ（暂时性死区），不是作用域问题。
2. 测试渲染的是**空画布**：`compList.length === 0` 走了三元表达式的另一个分支，
   那个按钮根本没被构建，于是那行引用从来没执行过。

**结论**：
- 空状态渲染只能证明「空状态不崩」。**「有数据」是另一条代码路径，必须单独喂种子状态测。**
- 补法是给垫片的 `useState` 按**调用序号**注入种子（画布 1 个精灵 + 选中它），
  并用「画布分区显示 1 个」这条文本反向确认种子确实生效 —— 否则测试等于在测空状态。
- 纪律：**组件体里所有 `useCallback` 一律声明在 JSX 之前**，别让板块去引用后面才定义的东西。

## 30. 给函数加了参数，`onClick` 直接把点击事件传了进去

**症状**：切图预览明明画出 8 个格子，点「切分为 8 张」却报「当前参数切不出内容」。

**事实**：0.14.0 给 `runSlice()` 加了 `(rectsArg, optsArg)`，但按钮仍写成 `onClick: runSlice`。
React 会把**点击事件对象**当第一个参数传进去：`rectsArg` 是个 Event，`rectsArg || previewRects`
里 Event 是 truthy，于是 `rects.length` 为 undefined，判空直接返回。

**为什么没测出来**：参数解构不报错，只有真点一下才暴露。当时改完跑了测试、也验了「一键切成帧」，
但没走「普通切分」这条路径。

**结论**：
1. 改函数签名时，**必须搜全仓调用点**（`runSlice` 当时有 2 处）。
2. 加了静态测试兜底：扫描 `onClick: 名字,` 再查该函数的 `useCallback` 签名，
   第一个参数非空就 FAIL。故意把 bug 改回去验证过，这条确实会红。
3. 剩下的 11 处 `onClick: 名字` 逐个核对过，都是无参函数。

## 31. 删重复监听时，连带删掉了 `addEventListener('keydown')`

**症状**：所有快捷键失灵 —— 删除、Ctrl+Z、Ctrl+C、Esc、空格全无反应。

**事实**：0.21.0 那轮我发现「粘贴」监听重复写了一份（`importFiles` 早就接好了），
于是把新加的那段删掉。删的时候把同一个 effect 里的
`window.addEventListener('keydown', onKey)` 也一起删了 —— 只剩清理函数
`return () => window.removeEventListener(...)`，所以解绑一个从来没注册过的监听，静默无事发生。

**为什么没测出来**：组件能正常渲染，130 项测试全过。
键盘事件是**注册在 window 上的副作用**，测试垫片根本不模拟事件派发。

**结论**：
1. 删代码时，**成对的东西要一起看**：注册/解绑、订阅/退订。
2. 加了静态检查：扫描所有 `addEventListener('x'`，要求存在对应的
   `removeEventListener('x'`，并且**单独钉死 keydown 必须存在**。
   反向验证过：把那行删掉，测试立刻红。
3. 教训升级：**「能被渲染测出来」不等于「功能还在」**。副作用（监听、定时器、网络）
   需要自己的检查方式，静态扫描是最便宜的一种。

## 32. 网格推断拿「角色宽度」当格子尺寸，列数系统性偏大

**症状**：自动推断出来的网格总是比实际多几列（9×4 的表推成 14×5，8×1 推成 13×1）。

**事实**：旧实现是 `cols = round(画布宽 / 中位盒子宽)`。
但角色通常比格子窄 —— 64px 的格子里只站 40px 宽的人，
576 / 40 ≈ 14，于是推成 14 列。**角色越瘦，错得越多。**

**正确做法**：用**相邻盒子的间距（pitch）**当格子尺寸。
同一行里相邻两格的 x 差就是列距，相邻行中心的 y 差就是行距；
格数仍然按整张画布算（空单元格也是格子，切的时候要对齐）。

```
cols = colPitch > 0 ? round(画布宽 / colPitch) : 1
rows = rowPitch > 0 ? round(画布高 / rowPitch) : 1
```

**中间踩的第二个坑**：我先改成「首尾跨度 / 间距 + 1」，结果
4 个盒子铺在原点的 128×128 画布上会被推成 2×2 —— 丢掉了「画布还有空白格」这层信息。
两条旧测试立刻挂掉，才发现方向错了：**间距用来定格子尺寸，画布尺寸用来定格数**，两者不能混。

**结论**：
1. 从数据推「结构」时，要找**周期**，不要找**尺寸**。周期不受个体胖瘦影响。
2. 单行/单列的表没有另一个方向的周期，那一维就是 1，不能拿盒子高度去凑。
3. 加了两条测试：四种布局（9×4 / 9×4 满格 / 8×1 / 宽度不齐的 6×2）都要推对，
   并显式断言 `cols !== 14`，防旧实现回来。
